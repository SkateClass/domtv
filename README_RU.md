# ЭФИР HOME 2.0 TEST

Отдельная новая тестовая система. Не заменяет рабочую 1.5.0 / HOME 2.2.
Новая архитектура, интерфейс, хранилище, API и Google-таблица. Никаких старых URL, PIN или токенов в пакете нет.
Это прототип для испытаний, не обещание безошибочной работы любого ТВ-потока.

## 1. Проверка без Google: да, достаточно GitHub Pages

1. Создайте НОВЫЙ репозиторий. Не перезаписывайте рабочий.
2. Распакуйте ZIP. Загрузите СОДЕРЖИМОЕ архива в корень репозитория: рядом должны лежать index.html, player.html, remote.html, assets/ и остальные файлы.
3. Settings → Pages → Deploy from a branch → main → /(root) → Save. Дождитесь успешной публикации.
4. Откройте выданный Pages-адрес. Не страницу просмотра кода на github.com.
5. Откройте «Плеер» и «Пульт» в ДВУХ вкладках ОДНОГО браузера одного профиля.
6. В плеере или пульте выберите «Тестовый эфир». Появится локально генерируемая картинка с часами. Для неё не требуется CDN, Google или рабочая телеканальная трансляция.
7. Из пульта проверьте остановку и перезапуск. Статусы должны меняться и в пульте.
8. В плеере нажмите «Имитировать сбой»: при включённом умном восстановлении он повторит попытку, затем сообщит об исчерпании источников. Для проверки перехода на резерв добавьте его в включённый сценарий.
9. Настройки → Экспорт настроек и каналов. Это ваша резервная копия, без ключей.

Важно: localStorage-режим работает только в одном браузере, профиле и origin. Он НЕ передаёт данные между телефоном и компьютером, между разными браузерами или приватными профилями. Два файла должны быть из одного репозитория. Просто двойной щелчок file:// не подходит: используются ES-модули и загрузка JSON.
Для локального HTTP без GitHub можно выполнить `python -m http.server 8080` из распакованной папки и открыть http://localhost:8080/.
Не закрывайте плеер во время теста. Пульт сам видео не воспроизводит.

## 2. Что включено

- Новый графитово-оливковый адаптивный интерфейс с лаймовым акцентом.
- Плеер для ПК и облегчённый пульт без загрузки видеобиблиотек до необходимости.
- 16 стартовых ТВ-каналов из прежнего продукта + синтетический тестовый эфир. Внешние источники помечены непроверенными.
- HLS через hls.js 1.5.17, DASH через dash.js 4.7.4, iframe/RUTUBE. Версии библиотек зафиксированы для воспроизводимости, не заявлены как последние.
- Низкое качество по умолчанию на HLS/DASH, ручной выбор и авто ABR.
- Ограниченный буфер и память. Контроль фактического продвижения видео, запуска, частых waiting и зависаний.
- Статусы idle/loading/playing/buffering/paused/blocked/recovering/error/stopped/unverified.
- Явные подтверждения команд с текстом ошибки, очередь и защита от повторной обработки последних 100 ID на клиенте. Это защита от обычных повторных запросов, не математическая exactly-once гарантия при аварийном закрытии вкладки между действием и сохранением результата.
- Один приёмник: Web Locks в поддерживаемом браузере для локального теста и серверная аренда в облаке. При отсутствии Web Locks локальная защита через lease в localStorage — best effort, не строгая межпроцессная гарантия.
- Канонический каталог публикуется только активным плеером. Пульт получает те же ID каналов/источников и версии каталога, не подставляет произвольные резервные URL.
- Архивирование и восстановление каналов/источников. Обновление не удаляет старые адреса и не возвращает архив самостоятельно.
- Шаблоны «Будний день», «Суббота», «Воскресенье», редактирование времени, дней, каналов и резервов. Изначально выключены.
- Импорт/экспорт настроек, каналов и сценариев; экспорт диагностики без серверных секретов.
- Импорт каналов старого JSON с массивом channels и streams/sources. Полный перенос всех старых настроек/сценариев 1.x не поддерживается: схемы различаются. JSONP-адреса, PIN и старые ключи из импорта не читаются.
- Обновление ru.m3u IPTV-org вручную либо каждые 6 часов при открытом активном плеере; автоматическое обновление первоначально выключено.

## 3. Новая таблица и Apps Script для телефона

В архиве нет физически созданной таблицы в вашем аккаунте: она создаётся функцией setup() после вашего разрешения. Рабочая старая таблица не затрагивается.

1. Создайте НОВЫЙ самостоятельный проект на script.google.com.
2. В Code.gs вставьте google-apps-script/Code.gs из пакета целиком.
3. По желанию включите отображение appsscript.json в настройках проекта и вставьте приложенный манифест. Часовой пояс Europe/Moscow; расписания клиента всё равно используют местное время ПК.
4. Выберите функцию setup → Выполнить → разрешите доступ. Стороннее непроверенное приложение требует самостоятельной проверки кода; организационная политика может запретить публичное развёртывание.
5. В журнале выполнения будут ссылка на НОВУЮ таблицу и случайный PIN. Запишите PIN. Повторный setup преднамеренно запрещён.
6. В таблице Settings!B2 можно изменить PIN на 6–12 цифр. Формат ячейки — текст. Проверка обновится максимум через 30 секунд; прежние сессии потеряют доступ после обновления проверки.
7. Развернуть → Новое развертывание → Веб-приложение → выполнять от вашего имени → доступ «Все». Нужен доступ без Google-входа на устройствах. Скопируйте URL, заканчивающийся /exec.
8. В плеере: Настройки → включите новый сервер Google → вставьте /exec → Сохранить режим и адрес → введите PIN → Войти. Обновите страницу плеера после настройки.
9. В пульте (на телефоне): аналогично укажите ТОТ ЖЕ НОВЫЙ /exec и PIN. Это другая сессия с ролью remote.
10. Дождитесь «на связи». Откройте «Тестовый эфир», затем проверьте телеканалы.
11. При изменении Code.gs публикуйте НОВУЮ ВЕРСИЮ существующего развёртывания. Сохранение исходника не обновляет опубликованный /exec.

Старая система HOME 2.2 НЕ совместима с этим API. Не вставляйте старый URL и не переносите старые токены. Не публикуйте таблицу «для всех»: публичным является веб-приложение с проверкой PIN/сессий.

### Структура новой таблицы
- Инструкция — пояснения.
- Settings — PIN.
- Devices — отпечатки выданных сессий, роль и время. Сырых токенов в таблице нет.
- Commands — история принятых команд с JSON. Не редактировать при работе.
- Events — резерв для ручных заметок и расширения, автоматическая запись всех событий в этой тестовой сборке не включена.
- CAT_* — неизменяемые снимки каталога, настроек и сценариев. Указатель на действующий снимок находится в Script Properties.

Команды и короткое состояние используют Script Properties, полные каталоги — листы CAT_*. Долгая запись снимка выполняется без общего lock; короткое переключение указателя защищено lock и проверкой аренды. Тяжёлые данные не записываются в один property.
Проверка результата POST выполняется отдельным запросом operation: непрозрачный no-cors ответ сам по себе не считается подтверждением.

### Обслуживание и ограничения Google
- Вручную запускайте cleanupSnapshots() после активных испытаний: сохраняется текущий и два предыдущих снимка, остальные CAT_* удаляются. НЕ запускайте во время публикации каталога.
- Commands и Devices хранят историю. Они автоматически не очищаются; для личного теста этого достаточно. Для длительного ежедневного использования потребуется ротация истории/ретенция и измерение квот.
- revokeAllSessions() отзывает все сессии новой системы. Кнопка «Отозвать эту сессию» отзывает текущую.
- Аренда приёмника истекает через 30 секунд без heartbeat. Второй плеер не захватывает живую аренду. Закройте старый и подождите минимум 30 секунд.
- Облачный цикл примерно раз в 4 секунды ПЛЮС задержка запросов. Это не WebSocket и не мгновенная связь. Для постоянного многомесячного использования нужно оценить реальные квоты Apps Script/Properties и нагрузку; бессрочная работа без квотных ошибок не гарантируется.
- Очередь до 20 команд, подтверждения последних 80 команд. Команда исполняется не позже 120 секунд после приёма сервером.
- Одна облачная команда до 45 КБ UTF-8, каталог до 2,5 МБ. Большой импорт выполняйте на ПК. Лимит интерфейса: 3000 каналов, отображается до 150 результатов поиска одновременно.
- Локальный тест не резервирует приёмник между разными браузерами: используйте один экземпляр.

## 4. Как работают сценарии и восстановление

Редактор: «Сценарии дня → Редактировать». Выберите шаблон или создайте новый, отметьте дни, добавьте время и канал, выберите резервы, сохраните. Из пульта изменение отправляется командой и применяется на ПК после подтверждения.
Резервы используются только у включённых сценариев, подходящих сегодняшнему дню. Порядок резервов — порядок каналов каталога. Для полного ручного упорядочивания резервов в этой тестовой сборке нет drag-and-drop.
Расписание исполняется активным ПК, не сервером. Выключенный/спящий ПК не включится сам. Действия после сна более двух минут не воспроизводятся задним числом. Не ставьте конфликтующие события в нескольких включённых сценариях на одно время.
Восстановление: одна повторная попытка → другие неархивные источники того же канала → резервы включённых сценариев текущего дня. До 20 попыток и 5 минут на цикл. Успех источника учитывается в локальном рейтинге; это история наблюдений, не гарантия доступности.
При pause, stop и блокировке autoplay автоматическое восстановление не должно перебивать пользователя. Нажмите Play на ПК один раз, если Chrome запрещает запуск со звуком. Пульт не может отменить ограничения браузера.
iframe/RUTUBE отмечаются unverified: приложение не выдаёт загрузившееся окно за работающую трансляцию, не может достоверно проверить его буфер и не запускает слепую ротацию таких источников. При необходимости выберите HLS/DASH или переключите источник вручную.

## 5. Безопасность и изоляция

Хранилище имеет префикс efir2.test + идентификатор пути репозитория. Ключи efir2 старого плеера и efir.home.* не читаются и не изменяются.
Новый Apps Script не содержит DB_ID/TOKEN старой системы. Создавайте именно НОВЫЙ проект, не вставляйте поверх рабочего Code.gs.
Не коммитьте свои сессии, PIN, экспорт с чужими приватными URL или заполненный адрес диагностики с token в репозиторий. Экспорт приложения специально исключает настройки соединения и сессии.
Любой владелец домашнего PIN может зарегистрировать пульт или плеер. Это личная домашняя модель доверия, а не многопользовательская система с администратором и отдельным правом сопряжения ПК. Для публичного сервиса нужна более сильная авторизация.
JSONP допустим здесь для совместимости статического сайта с Apps Script, но передаёт токен в URL запросов. Не делитесь такими адресами; используйте собственные устройства и HTTPS.
Внешние скрипты CDN и трансляции — внешняя зависимость. Нужны интернет, доступность CDN и соответствующие права на просмотр. Защитные заголовки/DRM/геоблокировки не обходятся.

## 6. Производительность и реальные ограничения

Приложение не обещает «идеально» на любом старом компьютере. Нужен поддерживаемый браузер с ES-модулями; для HLS через hls.js — MediaSource, для тестового эфира — canvas.captureStream. Старый ПК с актуальным Chrome/Edge/Firefox обычно подходит лучше старого браузера. Internet Explorer не поддерживается.
HLS/DASH: низкое качество на старте. HLS берёт минимальный bitrate из манифеста, DASH — нижний индекс качества. Выше можно выбрать вручную. При нативном HLS и iframe качество зависит от их собственного плеера.
Буфер ограничен по времени и памяти; он сглаживает краткие просадки, но не создаёт дополнительную пропускную способность. Если скорость постоянно ниже битрейта, снизьте качество/смените источник.
HTTP-источники на HTTPS-странице могут блокироваться, так же как CORS, DRM, геоблокировка, спецзаголовки и несуществующие адреса. Встроенные телеканальные URL в пакете не проверены в реальном эфире. Работоспособность синтетического теста не доказывает доступность ТВ-источников.
Загрузка обновлений и CDN зависит от сети. Нет фонового service worker: это сознательно исключает ещё один источник устаревшего кода при испытаниях. Нет фоновой работы при закрытой странице.
В этой сборке нет радио, EPG/XMLTV, записи эфира, серверного транскодирования, приложения Windows, push-пробуждения ПК, полного офлайн-режима или межустройственного управления без сервера. Эти функции не заявлены как готовые.

## 7. Что проверено разработчиком пакета

- Синтаксис всех JS и Code.gs через Node.
- 16 unit-тестов ядра: IDs, архив, слияние, aliases Russia 1/24, импорт M3U, валидация сценариев, расписание.
- 12 тестов серверной логики в mock-среде: роли, аренда, очередь, идемпотентность, подтверждения, публикация снимка, отзыв сессии.
- Ссылки на локальные ресурсы и целостность ZIP.

НЕ проверено здесь: настоящий браузерный запуск видео, ваш ПК/телефон, действующие эфиры, реальное развёртывание Google и реальные квоты. Это отдельный тестовый пакет, не production-сертификация.
Команды проверки при наличии Node 20+: `node tests/core.test.mjs` и `node tests/server.test.mjs`.

## 8. Если что-то не работает

1. Локально начните с «Тестового эфира», а не внешнего телеканала.
2. Пульт не видит ПК: проверьте общий браузер/профиль/Pages-origin либо одинаковый новый /exec и PIN в облаке.
3. «Другой плеер активен»: закройте лишние вкладки плеера; для облака дождитесь окончания аренды.
4. «Команда обработана» и чёрный экран: смотрите отдельный phase/detail. Это не обещание начала видео.
5. Нажмите Play внутри видео на ПК, если phase=blocked.
6. Настройки → Сохранить диагностику. В ней есть команда, результат и состояние. Сессию вручную искать и отправлять не нужно.
7. Не меняйте старую рабочую систему ради проверки этой версии.
